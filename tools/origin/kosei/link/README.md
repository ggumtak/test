# 네 줄을 한 이야기로: 부수·구성·유래·외우기 (2026-11-08)

사용자 요청: 부수·구성·유래·외우기 네 줄이 유기적으로 이어지는지, 설명이 이해하기 쉽고 연상하기 쉬운지 모두
검토해 고칠 것. "유래와 외우기가 서로 다른 말을 하기도 하고, 외우기를 봐도 무슨 말인지 연상이 안 되고 억지스러운
게 많다." 목표는 학습 효과.

## 기준 (`BRIEF.md`)
외우기가 다음 네 고리를 모두 지키고, 읽으면 장면이 그려지며 그 장면에서 뜻이 나오게 했습니다.
1. **같은 부품**: 구성 줄의 부품으로만 짓는다(属의 외우기에 구성에 없는 虫·冂를 쓰지 않음). 그릴 이름이 없는 부품만
   글자에 실제로 보이는 조각으로 부른다.
2. **같은 이름**: 구성 설명(또는 유래, 부수 줄의 뜻)과 같은 말로 부른다(警: 구성이 敬을 '조심하다'라 하면 '공경'이
   아니라 '조심'). 구성 설명이 모양의 출처만 말할 때(厶 黃을 줄인 꼴)는 보이는 모양의 뜻(나)으로 불러도 된다.
3. **같은 이야기**: 유래가 그림으로 그려지면 그 실제 이야기를 장면으로 다시 들려주고(取: 벤 적의 귀를 손에 쥠),
   그릴 수 없을 때만 지어내되 유래와 어긋나지 않는다(勢: 유래가 埶를 '나무 심는 모양'이라 하면 '재주'라 부르지 않음).
4. **같은 뜻**: → 뒤에는 훈음의 첫 훈과 일본어에서 쓰는 뜻.

유래·구성은 네 줄을 맞추는 데 필요한 만큼만(사실·유보 표현·음독·유형은 그대로), 부수와 사실 문제는 검토자가
`flags-N.tsv`에 근거와 함께 적고 리드가 판정했습니다.

## 방법
- **1차** (`make_inputs.py 16` → `in-N.txt`, 134자씩 16묶음): 묶음마다 작성(`BRIEF.md`) → 독립 검토(`REVIEW.md`).
  `link-N.tsv`가 검토를 거친 결과, `draft-N.tsv`가 작성자 원본. `check.py N`이 형식·길이(앱 테스트와 같은 UTF-16
  글자 수)·유형·음독·유보 표현·구성 모양과 역할 불변을 검사하고, `rules.py`의 자동 점검(구성에 없는 부품, 다른 이름,
  빠진 부품, → 뒤 뜻)을 참고로 보여 줌. 1묶음을 먼저 시범으로 돌려 지침을 고친 뒤(짧게 쓰기, 검토자 엄격하게)
  나머지 15묶음을 돌림.
- **리드 결정** (`link-lead.tsv`, 2차 전에 적용): 검토자 지적 12건 판정과 묶음 사이 통일(아래).
- **2차** (`round2/`, 267자씩 8묶음, `CRITIC.md` → `VERIFY.md`): 병합된 카드를 처음 보는 점검자가 아직 실패하는
  줄만 고치고, 다른 확인자가 그 줄마다 옛 줄이 정말 실패였는지 따져 불필요한 변경을 지움. 1차의 교훈을 지침에 넣음:
  구성 이름을 기계적으로 따르다 생긴 억지(膨 '성씨 팽' → '팽씨 아저씨')는 자료(kanji.tsv)에 있는 그 부품의 다른
  훈으로 구성 설명과 외우기를 함께 바꿈(북소리 팽). 이야기 안에 뜻이 들어 있는 것은 정상(枝 '뻗은 가지 → 가지').
- **마지막 손질** (`link-final.tsv`): 2차 뒤 묶음 사이 이름 통일(渡 沿 鉛 剣), 눈가림 채점 뒤 7자(아래).
- `../merge.py`는 link-N → link-lead → round2/fix-N → link-final 순서로, 다른 모든 보정 파일 다음에 적용.
- `stats.py`(자동 점검 수치), `names.py`(같은 부품을 외우기마다 어떤 말로 부르는지), `ship_check.py`(Android SDK
  없이 앱 테스트 `PartsTest.shippedOrigins`와 같은 검사).

## 결과
- 1,338자를 바꿈: 외우기 1,329줄(마지막 7자 포함), 구성 설명 40줄, 유래 1줄(畝), 부수 이름 5자(아래). 2차는 그중 91줄을 더 고침
  (점검자가 고친 164줄 가운데 73줄은 확인자가 불필요한 변경으로 지움).
- 자동 점검(`stats.py`, 작업 전 → 후): 힌트가 걸린 글자 871 → 389, 구성에 없는 부품 367 → 144, 빠진 구성 부품
  196 → 45, → 뒤 뜻 불일치 67 → 26, 어려운 말 33 → 11. 남은 힌트는 대부분 허용된 경우(이름 없는 부품을 보이는 조각으로 부름,
  활용형 차이, 어려운 말이 곧 그 글자의 뜻: 塁 보루, 庁 관청). 외우기 길이 중앙값 26 → 30자, 40자 넘는 줄 2줄.
- 눈가림 채점: 무작위 150자의 작업 전 카드와 작업 후 카드를 서로 다른 채점자(Claude)에게 같은 기준(네 고리 +
  그림)으로 주고, 어느 쪽이 전·후인지 알리지 않음. 불합격은 작업 전 31자(21%: 이름 있는 부품을 조각으로 쪼갬, 구성과
  다른 이름, 유래와 어긋남, 장면 없음), 작업 후 1자(読, 0.7%). 読은 유래가 "賣(팔다)와 다른 글자"라 하는데 '파는(売)'으로
  그렸던 것으로, 같은 유형(유래가 "X와 다른 글자"라 밝힌 부품을 X의 뜻으로 부름) 7자를 모두 보이는 조각으로 고침:
  読 続(売 → 士·冖), 話 活 括(舌 → 千·口), 肺 姉(市 → 亠·巾). 채점자도 모델이라 사람의 판단과는 다를 수 있음.

## 리드 판정 (`link-lead.tsv`, `link-final.tsv`)
- **받아들임**
  - 부수 이름: 命·器의 口와 聖의 耳는 왼쪽 변이 아니라 くちへん·みみへん이 아님 → くち·みみ. 琴의 王王은 위에 있어
    おうへん이 아님 → たま. 玉은 글자 자체가 부수라 王이 아닌 玉으로(`../../../build_parts_data.py`의
    `RADICAL_FIX`, 앱의 `parts.tsv`도 같게 고침). 부수 줄 이름은 KanjiVG가 준 위치로 고르므로 상용한자 전체를 위치별로
    다시 훑었고, 틀린 것은 이 넷(지적 2자 + 琴·聖)과 玉뿐이었음.
  - 炭: 구성을 획 그림 색(山+厂 파랑, 火 빨강)과 유래대로 `山+厂(岸을 줄인 꼴 · 소리) + 火(불 · 뜻)`로 나눔.
  - 成·憩: 부수를 품은 부품에 '안에 부수' 표시(戚·慮와 같게). 虐: 유래가 이름까지 든 두 부품으로 구성 줄을 둠.
  - 畝: 구성에 보이는 久의 출처를 유래에 보탬(옛 사전 說文: 畞, 畮或从田十久).
  - 荅: 근거 없는 훈 '젖을 답'(kanji.tsv의 答 훈에서 옮겨 온 것) 대신 搭과 같은 '대답 답'.
  - 묶음 사이 통일: 云(魂·雲 '구름을 그린 꼴'), 冓(溝·講·購 '나무를 엇갈려 쌓음'), 几(飢 '작은 상', 机·肌 '몸을
    기대는 받침'), 㕣(沿·船·鉛 '산속의 늪'), 㑒(剣·検·険·験 '모두'), 渡의 度('법도 도·헤아릴 탁': 소리 ド와 외우기의
    '헤아려'를 함께 잇게).
- **반영하지 않음**
  - 屯: '첫 획이 가로획 一'이라는 지적은 획 자료와 다름. 획 중심선이 (645,182)에서 (234,355)로, 오른쪽 위에서 왼쪽
    아래로 그어지는 납작한 삐침(丿)이고(지적은 외곽선의 시작점을 획 방향으로 읽음), 이전 검토(`../gemini/v-2.md`)의
    판정과도 같음.
  - 華: 보이는 조각으로 나눌 수 없는 그림 글자라 구성 줄을 일부러 없앤 글자.
  - 由·甲·申: 부수 田이 글자 전체의 테두리라, 글자 전체가 부수인 글자처럼 칠하지 않음.

## 외부 검토 반영 (2026-11-08, `link-gemini.tsv`, 코드·부수 이름표)
`current_kanji_structure.md`를 제미나이가 검토한 개선안(Kanji_4step_Review_And_Improvement_Plan.md)의 작업 4가지를,
근거가 확인되는 범위에서 적용했습니다.

1. **부수 줄 안내** (`Parts.kt`의 `Kosei.radicalOnlySound`·`radicalHere`, `LookupActivity.radicalText`, 테스트
   `PartsTest.radicalNotes`)
   - '사전 분류용(여기서는 소리 쪽)'은 부수가 소리만 낼 때만: 부수 부품이 뜻과 소리를 함께 맡는 13자(酒 字 知 散
     愛 憂 如 幼 幽 既 疎 耐 致)에서 빠짐(65 → 52자).
   - 구성이 부수 부품을 부수 이름과 다른 말로 부르면 부수 줄 끝에 `여기서는 '뚜껑'`(会), `여기서는 '배 舟가 변한 꼴'`
     (服)처럼 이어 줌(124자). 부수 부품이 모양·기호이거나 '~가 변한/줄인 꼴'인 경우만. 개선안의 '사전 분류용(여기서는
     X 모양)'이라는 말은 쓰지 않음: 審의 宀(덮다)처럼 부수가 뜻을 맡으면서 설명만 다른 글자가 있어서.
2. **부수 이름표 뜻 보강** (`../../radmeaning.tsv` → `../../apply_radmeaning.py`): 상용한자가 쓰는 줄 가운데 이름만으로
   글자 속 역할을 알 수 없는 51줄(戸 지게 호 → 외짝 문, 卩 병부 절 → 무릎 꿇은 사람, 厶 마늘 모 → 사사로움·나, 缶 장군
   부 → 항아리, 示 → 제단·신, 酉 → 술독·술, 斤 → 도끼, 欠 → 입 벌린 사람, 又 → 손, 寸 → 손·법도 등). '흙 토(흙)'처럼
   이름이 뜻을 이미 말하는 줄은 이름표의 원래 규칙대로 비워 둠.
3. **지금 모양으로 부르기**: 유래가 본래 다른 글자라 밝히지만 지금은 아는 글자와 같은 모양인 부품은 그 글자로
   (話·活·括 혀 舌, 読·続 팔 売, 姉·肺 시장 市). 그 전 작업에서 보이는 조각(千·口, 士·冖, 亠·巾)으로 바꿨던 7자를
   되돌림. 乾의 𠦝(글꼴에 드묾)은 보이는 十+早로. 㑒는 다섯 자 모두 구성 설명에도 '모두'.
4. **그림이 안 되는 소리 부품의 훈 통일**(45자): 其 → 곡식 키(箕의 원래 글자), 曽 → 시루(甑의 원래 글자, 曽 카드의
   유래), 且 → 도마·위패(且 카드의 유래), 莫 → 해가 풀숲에 짐(暮 카드의 유래), 甫 → 모종 돋은 밭, 者 → 사람(자료의
   훈 '사람 자'), 由 → 지날 유(자료의 훈, 宙·笛·袖·軸과 같게), 也 → 구불구불한 꼴(유래가 확실치 않아 모양으로만).

**바꿔 적용하거나 반영하지 않은 것**
- 且 '층층이 쌓은 단', 其 '네모 틀·달력 틀', 由 '병 주둥이': 근거가 없는 해석이라 각 카드의 유래·원래 뜻으로 바꿈.
- 曷 '목청껏 외칠 갈': 曷의 훈(어찌·그칠)에도 유래에도 없는 뜻이라 반영하지 않음. 지금 외우기의 '어찌 ~!'는
  감탄하는 장면으로 그려져 그대로 둠.
- 話·括의 '본래 모으다 뜻의 글자': 근거가 약해 유래에 넣지 않음(유래는 '지금은 舌 꼴로 씀'을 그대로).
- 塞의 '井' 꼴: 塞 윗부분은 가로획이 셋이라 井과 다름. 亜의 '십자(+) 제단': 보이는 모양이 아님.
- 소리 계열 줄의 배지, AI 프롬프트 【외우기】 규칙 통일, 불명 글자의 문장 순서: 개선안 본문에는 있으나 실행
  프롬프트(작업 1–4)에 없어 이번에는 하지 않음.

### 후속 반영 (같은 날)
- **其의 '키'**: '키(其)'만으로는 열쇠·신장으로 읽혀, 6자(基 期 棋 碁 欺 旗)의 외우기를 모두 '곡식 키(其)'로.
  ('키만 한 천'처럼 신장으로 읽히던 旗도 고침.)
- **曷 6자(渇 喝 掲 謁 葛 褐)**: 추상어 '어찌' 대신, 曷에 보이는 조각 匃(kanji.tsv 훈음 '빌 개')로 장면을 만듦(渇 '물
  한 모금만 달라고 빌고 또 비는', 謁 '만나 주십사 비는'). 구성 설명은 '어찌 갈, 曰+匃 꼴'로 모양만 밝힘: 曰+匃가
  뜻을 합쳐 이루었다고는 하지 않음(옛 사전 說文은 匃를 소리 부분으로 봄).
- **소리 계열 줄** (`LookupActivity.familyHead`·`familyText`): 앞에 같은 소리 부품을 소리 색으로, 그 카드의 구성이
  부르는 이름과 함께 보여 주고(`青(푸를 청) 계열: 清 情 精 請  セイ`, `且(도마·위패) 계열: …`), 소리 부품 자신은 목록에서
  뺌(비교 버튼에는 남음). 구성의 이름이 길거나 한자가 섞이면 모양만(`其 계열: …`), 구성 줄이 없는 글자는 훈음.
- **AI 설명의 【외우기】** (`KanjiText.SYSTEM_PROMPT`, 테스트 `KanjiTextTest`): 카드와 같은 형식(`- 장면 → 뜻`, 부품은
  `이름(모양)`, 괄호에는 읽기가 아니라 모양), 보이는 부품만, 장면 하나에서 뜻이 나오게, 약 40자 이하, 유래가 그림이면
  다시 들려주고 아니면 어긋나지 않게, 소리만 내는 부품은 그림이 되는 이름(본래 그린 것·다른 뜻·보이는 모양)으로 부르고
  추상어(그·또·어찌·일찍·어조사)는 쓰지 않음.
- `current_kanji_structure.md`의 상용한자 표에 '소리 계열' 칸을 더함.

## 외부 검토 2차 반영 (2026-11-08, `link-round3.tsv`, 코드)

'해(曷)'는 曷 전체를 日로 부르는 것이라 오히려 맞지 않습니다.

- **구성 설명 빈칸 0개로** (46자): 역할은 있는데 설명이 비어 있던 부품을 채움. 설명은 kanji.tsv의 한국어 훈음 →
  없으면 kanji.tsv의 영어 뜻(畐 'to fill' → 가득 찬 항아리, 朿 'thorn' → 가시, 隺 'bird flying' → 높이 나는 새) →
  없으면 외우기가 쓰는 보이는 조각('艹+隹+又 꼴') 순. 같은 부품은 같은 이름으로(畐 = 富·福과 같은 항아리, 啇 =
  嫡·摘·敵과 같은 밑동, 丩 = 糾와 같은 얽힘, 戠 = 職과 같은 '音과 戈를 합친 꼴', 𢦏 = 裁와 같은 '다칠 재'), 丂 네
  글자는 목·꼬불꼬불·갈고리·지팡이로 제각각이던 이름을 '굽은 꼴'로 통일. 2차 안은 菐·叚·堇 등의 훈음이 kanji.tsv에
  있다고 했으나 실제로는 비어 있어, 이 셋은 한국 한자 사전의 표준 훈(번거로울 복, 빌 가, 진흙 근)을 씀.
  외우기도 맞춤: 幅 '밭(畐)' → 항아리, 適의 구성에 없는 古 → 밑동, 말장난 '복(菐)싱'·'유(俞)쾌'·'적(啇)은' 뺌.
- **다리 설명** (42자): '~을 줄인 꼴'로만 적혀 외우기의 이름과 이어지지 않던 부품에 지금 모양의 이름을 함께 적음
  (`구역 区, 區를 줄인 꼴`, `자 尺, 睪을 줄인 꼴`, `구십 卆, 卒을 줄인 꼴`, `오를 양 襄을 줄인 꼴` 등, 16자 이내).
- **남은 추상 훈**: 未 → 아직 미(4자), 呉 → 머리 젖혀 큰소리침(呉 카드의 유래, 3자, '오(呉)해' 같은 말장난 뺌),
  非 → 등진 두 날개(非 카드의 유래, 排·輩·扉), 是 → 곧을 시(堤).
- **'유래 불확실' 4자**(丸 匹 由 真): 본문이 '확실하지 않음'으로 시작해 라벨과 같은 말이 겹치던 것을, 풀이를 앞에
  두고 유보 표현을 뒤로(사실·유보 그대로). 由의 외우기는 구성(日+丨)에 없는 밭(田) 대신 유래의 등잔으로.

  없는 글자(상용 밖 11,298자 등)의 자동 구성은 부수 모양의 부품에 부수 이름표의 쉬운 뜻을 씀(`Radical.meaningOf`:
